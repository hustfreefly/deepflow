## DeepFlow 是什么

DeepFlow 是一个**多 Agent 管线框架**，运行在 OpenClaw 平台上。核心职责是将用户的自然语言需求转化为可执行的工程方案。

**核心原则**: 代码做确定性粗筛，LLM 做语义判断。

## DAL (Domain Adaptation Layer)

DAL 是 DeepFlow V2.1.1 新增的**域自适应层**，让系统无需硬编码规则即可处理不同领域的需求。

### 设计原则

| 原则 | 说明 |
|:---|:---|
| LLM 域自推断 | 不用 if/else 判断领域，LLM 从需求文本推断 |
| 4 域 YAML 参考 | software/investment/hardware/business 仅作 few-shot |
| 零配置接入 | 新领域不需要改代码，LLM 自动适配 |
| 全链路透传 | DomainProfile 从 Spec Pro 贯穿到 Ship Pro |

### 数据流

```
Spec Pro                          Solution Pro                    Ship Pro
─────────                         ────────────                    ────────
parse.md 推断 domain_id    →      domain_analysis.py       →      context.json
         生成 DomainProfile       生成 DomainProfile               裁剪 Worker 上下文
         注入域上下文               透传到各模块
```

### 关键文件

| 文件 | 职责 |
|:---|:---|
| `domains/spec_pro/domain_context.py` | 构建域上下文，注入 prompt |
| `domains/solution_pro/domain_analysis.py` | LLM 推断 DomainProfile |
| `domains/solution_pro/config/domains/*.yaml` | 4 域 few-shot 参考 |
| `domains/solution_pro/spec_context.py` | Spec 上下文提取 |

## 三层门控架构

DeepFlow 的质量保障采用三层门控，每层职责分明:

```
LLM 输出
    │
    ▼
┌──────────────────────────────────┐
│ L1: 确定性检查 (代码)            │  ← 快速、零成本
│  - Pydantic Schema 验证          │
│  - 字段存在性                    │
│  - 类型检查                      │
│  - 格式约束                      │
└──────────────────────────────────┘
    │ 通过
    ▼
┌──────────────────────────────────┐
│ L2: 语义检查 (LLM)              │  ← 理解含义
│  - 语义合理性                    │
│  - 架构健全性                    │
│  - 原则一致性                    │
│  - 质量评估                      │
└──────────────────────────────────┘
    │ 评分
    ▼
┌──────────────────────────────────┐
│ L3: 合并决策 (代码)              │  ← 最终裁决
│  - L1 + L2 结果合并              │
│  - PASS / CONDITIONAL / FAIL    │
│  - 是否进入下一轮/阶段           │
└──────────────────────────────────┘
```

### 在各域的体现

| 域 | L1 (代码) | L2 (LLM) | L3 (合并) |
|:---|:---|:---|:---|
| Spec Pro | `contracts/gate.py` Pydantic | `harness.md` 评估 | `gate_harness_decision()` |
| Solution Pro | `schemas/` Pydantic | `auditor_harness.md` | `harness_scoring.py` |
| Ship Pro | `PipelinePlan` Pydantic | `consolidator.md` | `pipeline_designer.py` |

## AI Native 设计原则

| # | 原则 | 实践 |
|:---|:---|:---|
| 1 | 代码做确定性粗筛 | Pydantic 验证、格式检查、字段过滤 |
| 2 | LLM 做语义判断 | 域推断、质量评估、方案评审 |
| 3 | 不用 if/else 做分类 | 域判断用 LLM，不用关键词匹配 |
| 4 | 不用正则做语义匹配 | 需求追踪用 semantic anchors，不用 regex |
| 5 | Prompt 是协作契约 | Role + Context + Constraints + Examples + Output |
| 6 | 错误恢复是 LLM 诊断 | 不 try/except 硬回退，LLM 分析错误再决策 |

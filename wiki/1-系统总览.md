# DeepFlow 系统总览

> 三域协作的 AI 原生解决方案生成框架  
> 最后更新：2026-06-22

---

## 系统架构

```
用户输入
   ↓
┌─────────────────────────────────────────────────────┐
│  Spec Pro (需求规格域)                               │
│  ─────────────────────                               │
│  Coordinator 管理多轮对话                             │
│  ResponseWorker 提取需求                              │
│  merge_spec 合并到 LivingSpec                         │
│  Harness V2 评估质量                                  │
│                                                      │
│  输出: LivingSpec (需求规格)                          │
└─────────────────────────────────────────────────────┘
   ↓
┌─────────────────────────────────────────────────────┐
│  Solution Pro (解决方案域)                           │
│  ─────────────────────────                           │
│  10 阶段管线:                                        │
│  Planner → Reviewer → Fixer → Researcher →          │
│  Consolidator → Auditor → Fixer → Harness →         │
│  Fixer → Summarizer                                 │
│                                                      │
│  输出: final_result.json (技术方案)                   │
└─────────────────────────────────────────────────────┘
   ↓
┌─────────────────────────────────────────────────────┐
│  Ship Pro (工程交付域)                               │
│  ─────────────────                                   │
│  5 Agent 流水线:                                     │
│  Architect → Specifier → Decomposer →               │
│  Packager → Reviewer                                │
│                                                      │
│  输出: ship_package.json (可执行工程包)              │
└─────────────────────────────────────────────────────┘
```

## 核心数据流

### 1. 需求规格流 (Spec Pro)

```
用户对话 → ResponseWorker → response.json
                              ↓
                    merge_spec.py → LivingSpec
                                      ↓
                              Harness V2 评估
```

**关键文件**:
- `domains/spec_pro/coordinator.py` - 对话编排
- `domains/spec_pro/merge_spec.py` - 需求合并
- `domains/spec_pro/eval/harness.py` - 质量评估
- `domains/spec_pro/prompts/` - 10 个 prompt 模板

### 2. 解决方案流 (Solution Pro)

```
LivingSpec → 10阶段管线 → 每阶段产出 stage_X.json
                              ↓
                    final_result.json (最终方案)
```

**关键文件**:
- `domains/solution/orchestrator_agent.py` - 管线编排
- `domains/solution/task_builder.py` - 任务构建
- `domains/solution/spec_context.py` - 上下文注入
- `domains/solution/prompts/` - 25 个 prompt 模板

### 3. 工程交付流 (Ship Pro)

```
final_result.json → Architect → Specifier → Decomposer
                                             ↓
                    Packager ← ship_package.json ← Reviewer
```

**关键文件**:
- `domains/ship_pro/scripts/orchestrator.py` - 编排
- `domains/ship_pro/eval/gates.py` - 质量门控
- `domains/ship_pro/prompts/` - 9 个 prompt 模板

## 共享基础设施

### Blackboard (黑板系统)

所有域的输入输出都存储在 `blackboard/` 目录：

```
blackboard/
├── spec_spec_XXX/           # Spec Pro 会话
│   ├── input.md             # 用户原始输入
│   ├── spec/
│   │   ├── living_spec.json # 需求规格
│   │   └── harness_report.json
│   └── stages/              # 中间产物
│
├── solution_XXX/            # Solution Pro 会话
│   ├── input.json           # LivingSpec 输入
│   ├── stage_1_planner.json
│   ├── stage_2_reviewer.json
│   ├── ...
│   └── final_result.json    # 最终方案
│
└── ship_XXX/                # Ship Pro 会话
    ├── input.json           # 技术方案输入
    ├── architect_output.json
    ├── ...
    └── ship_package.json    # 工程包
```

### PathConfig (路径管理)

所有路径操作通过 `core/config/path_config.py` 统一管理：

```python
from core.config.path_config import PathConfig

# 获取项目根
root = PathConfig.get_project_root()

# 获取 blackboard 路径
bb = PathConfig.get_blackboard_path()

# 获取会话路径
session = PathConfig.get_session_path("spec_spec_123456")
```

### Cage (契约笼子)

Prompt 版本和兼容性通过 `cage/active/` 管理：

```
cage/active/
├── spec_pro_cage.json    # Spec Pro prompt 版本约束
├── solution_pro_cage.json # Solution Pro prompt 版本约束
└── ship_pro_cage.json    # Ship Pro prompt 版本约束
```

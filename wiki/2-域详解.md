## 1. Spec Pro

> **版本**: V2.2.0 | **测试**: 52 | **Prompts**: 8 | **Modules**: 18

### 职责

需求收集与结构化。通过苏格拉底式多轮对话，将用户模糊需求转化为结构化的 LivingSpec。

### 核心工作流

```
用户输入 (自然语言)
    │
    ▼
SpecProCoordinator.init_session()
    │
    ├─→ BlackboardManager 创建 session 目录
    ├─→ 构建 task prompt (parse.md)
    │     └─→ 域自推断: LLM 从输入推断 domain_id
    │     └─→ domain_context.py 注入域上下文
    │
    ▼
Worker Agent (sessions_spawn)
    │
    ├─→ parse.md: 解析输入 → 结构化 JSON
    ├─→ structure.md: 提取需求维度
    ├─→ guide.md: 生成引导问题
    │
    ▼
Coordinator 读取 Worker 输出
    │
    ├─→ merge_spec.py: 合并到 LivingSpec
    ├─→ contracts/gate.py: L1 Pydantic 验证
    ├─→ harness: L2 LLM 评估 + L3 合并决策
    │
    ├─→ 质量不够? → 下一轮对话 (最多 max_rounds)
    └─→ 质量达标? → build_handoff_package() → 交接给 Solution Pro
```

### 三层门控

| 层 | 实现 | 验证内容 |
|:---|:---|:---|
| L1 | `contracts/gate.py` | LivingSpec Pydantic Schema、字段存在性、类型 |
| L2 | `harness.md` | 语义完整性、需求覆盖度、歧义检测 |
| L3 | `gate_harness_decision()` | 合并 L1+L2 → PASS / CONDITIONAL / FAIL |

### 关键文件清单

| 文件 | 职责 |
|:---|:---|
| `coordinator.py` | 主Agent侧协调器 (22 functions)，管理 session 生命周期 |
| `blackboard.py` | BlackboardManager 封装 |
| `merge_spec.py` | 合并用户回复到 LivingSpec |
| `models.py` | DialogState, LivingSpec, Scenario 等数据模型 |
| `schemas.py` | 空状态常量定义 |
| `domain_context.py` | 域上下文构建 (DAL) |
| `handoff.py` | 构建交接包给 Solution Pro |
| `contracts/gate.py` | L1 门控 (Pydantic 验证) |
| `contracts/living_spec.py` | LivingSpec Pydantic 模型 |
| `response_normalizer.py` | Worker 输出标准化 |
| `process_guard.py` | 流程守卫 (安全阀) |
| `requirement_structuring.py` | 需求结构化逻辑 |
| `worker_fallback.py` | Worker 失败降级 |

### DAL 在 Spec Pro 的体现

1. `parse.md` 包含域自推断 prompt — LLM 从输入文本推断领域
2. `domain_context.py` 根据推断的 domain_id 构建域上下文
3. 域上下文注入到后续所有 prompt 中 (guide.md, structure.md, assess.md)

## 2. Solution Pro

> **版本**: V2.1.1 | **测试**: 137 | **Prompts**: 39 | **Modules**: 26

### 职责

方案设计与评审。接收 LivingSpec，通过 Planning → Research → Summary 三模块串联，输出完整技术方案。

### 核心工作流

```
LivingSpec + Handoff Package
    │
    ▼
MasterOrchestrator (master_orchestrator.py, 29 functions)
    │
    ├─→ [Module 1] PlanningOrchestrator (planning_orchestrator.py)
    │     │
    │     ├─→ MetaPlanner: 分析需求，规划需要哪些专家
    │     ├─→ Expert Agents (并行): 各领域专家独立设计
    │     │     ├─→ planning_expert_base.md
    │     │     └─→ expert_planner_base.md
    │     └─→ Convergence: 收敛多专家方案
    │           └─→ convergence_planner.md
    │
    ├─→ [Module 2] ResearchOrchestrator (research_orchestrator.py)
    │     │
    │     ├─→ ResearchPlanner: 确定研究问题
    │     ├─→ Researcher Agents (并行): 多方向调研
    │     │     └─→ research_expert_base.md
    │     └─→ 输出: research_results.json
    │
    └─→ [Module 3] SummaryOrchestrator (summary_orchestrator.py)
          │
          └─→ 5+1 Phase 收敛:
              ├─→ Phase 1: Analyzer (并行) → 多维度分析
              ├─→ Phase 2: BaseSynthesizer → 基础综合
              ├─→ Phase 3: Refiner → 精炼
              ├─→ Phase 4: MetaPlanner → 元规划审查
              ├─→ Phase 5: JSONExtractor → 结构化输出
              └─→ +1: FixAgent (条件) → 修复不一致
          │
          └─→ final_result.json
```

### MasterOrchestrator 特性

| 特性 | 说明 |
|:---|:---|
| 极简调度 | 不做语义判断，只做模块顺序调度 |
| 双层状态 | master_state.json + module_state.json |
| 断点续跑 | skip_completed + 双层 state 验证 |
| 差异超时 | Planning 5min / Research 15min / Summary 20min |
| 错误隔离 | ModuleFailure 不影响其他模块的已完成输出 |
| PipelineWatcher | 运行时可观测性 |

### 关键文件清单

| 文件 | 职责 |
|:---|:---|
| `master_orchestrator.py` | 三模块串联调度器 (29 functions) |
| `planning_orchestrator.py` | Planning 模块调度 |
| `research_orchestrator.py` | Research 模块调度 |
| `summary_orchestrator.py` | Summary 模块 (5+1 Phase) |
| `domain_analysis.py` | DAL: LLM 推断 DomainProfile |
| `spec_context.py` | Spec 上下文提取 |
| `module_orchestrator_base.py` | 模块编排基类 |
| `convergence_layer.py` | 方案收敛层 |
| `harness_scoring.py` | Harness 评分 |
| `ai_native_auditor.py` | AI Native 审计 |
| `compliance_checker.py` | 合规性检查 |
| `information_conservation.py` | 信息守恒验证 |
| `pipeline_watcher.py` | 运行时可观测性 |
| `pipeline_exceptions.py` | 管线异常定义 |
| `control_contract.py` | 控制契约 |
| `blackboard.py` | BlackboardManager |
| `state_manager.py` | 状态管理 |
| `task_builder.py` | 任务 prompt 构建 |

### DAL 在 Solution Pro 的体现

1. `domain_analysis.py` 接收 Spec Pro 的 DomainProfile 或重新推断
2. `config/domains/*.yaml` (software/investment/hardware/business) 作为 few-shot 参考
3. DomainProfile 透传到 Planning/Research/Summary 各模块的 prompt 中
4. 16+ prompt 已泛化，包含多域示例

## 3. Ship Pro

> **版本**: V2.0.0 | **测试**: 19 | **Prompts**: 1 | **Modules**: 3

### 职责

交付包生成。将 Solution Pro 的技术方案拆分为可执行的 Work Packages。

### 核心工作流

```
final_result.json (Solution Pro 输出)
    │
    ▼
PipelineDesigner (pipeline_designer.py)
    │
    ├─→ 分析方案结构
    ├─→ 设计 Worker 拆分方案
    ├─→ 为每个 Worker 裁剪 context.json (≤3KB)
    └─→ 输出: PipelinePlan (Pydantic 验证)
    │
    ▼
Orchestrator (调度层)
    │
    ├─→ Worker Agents (并行)
    │     ├─→ 每个 Worker 生成 Work Packages
    │     └─→ 覆盖指定 REQ-ID
    │
    ▼
Consolidator (consolidator.md)
    │
    ├─→ 合并所有 Worker 输出
    ├─→ 去重 + 依赖排序
    └─→ ship_package.json
```

### 镜像架构

Ship Pro V2.0.0 采用与 Solution Pro 镜像的架构:

| Solution Pro | Ship Pro |
|:---|:---|
| MasterOrchestrator | Orchestrator |
| PlanningOrchestrator | PipelineDesigner |
| SummaryOrchestrator | Consolidator |
| Pydantic schemas | PipelinePlan Pydantic |

### 关键文件清单

| 文件 | 职责 |
|:---|:---|
| `pipeline_designer.py` | 分析方案 → 设计 Worker 拆分 → Pydantic 验证 |
| `conservation_judge.py` | 信息守恒判断 |
| `prompts/consolidator.md` | 合并 Worker 输出的 prompt |

### 契约笼子

- `WorkerSpec` Pydantic: role (≥3字), module_purpose (≥20字), covered_req_ids (≥1), estimated_wps (3-12)
- `PipelinePlan` Pydantic: workers 列表 + 依赖拓扑验证
- context.json 大小 ≤ 3KB (自动裁剪)

## 4. Deliver Pro

> **版本**: V1.0.0 | **测试**: 213 | **Prompts**: 6 | **Modules**: 5

### 职责

执行与交付。消费 Ship Pro 输出的 Work Packages，通过 5 Phase 流水线生成最终交付物。

### 核心工作流

```
ship_package.md (Ship Pro 输出)
    │
    ▼
P1: Analyze (LLM Agent)
    │  → execution_plan (任务分解 + 依赖图)
    ▼
P2: Generate (LLM Agent × N, 并行)
    │  → Worker 输出 (每个 WP 的完整内容)
    ▼
P3: Integrate (Code-First Assembly, 零 LLM)
    │  → smart_assembler.py: 读文件 → 标题归一 → 物理拼接 → TOC
    │  → 保留率 ≥95% (不变量: len(final) >= sum(len(worker.content)))
    ▼
P4: Validate (LLM Judge)
    │  → 6维度评分 + 保留率门禁
    ▼
P5: Package (LLM Agent)
    │  → deliver_final.md + 元数据
```

### 关键文件清单

| 文件 | 职责 |
|:---|:---|
| `smart_assembler.py` | Code-First Assembly 引擎 (~200行) |
| `orchestrator.py` | 5 Phase 流水线调度 |
| `contracts/execution_plan.py` | 执行计划 Pydantic 模型 |
| `contracts/worker_output.py` | Worker 输出 Pydantic 模型 |
| `contracts/deliver_package.py` | 交付包 Pydantic 模型 |
| `contracts/validation_verdict.py` | 验证裁决 Pydantic 模型 |

### Code-First Assembly 核心设计

- **问题**: LLM 做“合并”会摘要压缩（264KB → 42KB，84% 丢失）
- **解决**: Python 确定性拼接（读文件 → 标题归一 → 物理拼接 → TOC → 写文件）
- **效果**: 264KB → 371KB（保留率 100.8%），零 LLM 调用
- **不变量**: `len(final) >= sum(len(worker.content))`（只增不减）

## 5. Research Pro

> **版本**: V2.0.0 | **测试**: 136 | **Prompts**: 8 | **Modules**: 10

### 职责

深度研究引擎。独立域，不依赖主链路。用于技术调研、竞品分析、市场研究等。

### 核心工作流

```
研究主题
    │
    ▼
Orchestrator (orchestrator.py)
    │
    ├─→ KeywordGenerator: 生成搜索关键词
    ├─→ DDGS Client: DuckDuckGo 搜索
    ├─→ SafeFetcher: 安全抓取网页内容
    ├─→ TierClassifier: 来源分级 (T1-T4)
    ├─→ CitationVerifier: 引用验证
    │
    └─→ 分析报告生成
```

### 关键文件清单

| 文件 | 职责 |
|:---|:---|
| `orchestrator.py` | 研究编排器 |
| `keyword_generator.py` | 搜索关键词生成 |
| `ddgs_client.py` | DuckDuckGo 搜索客户端 |
| `safe_fetcher.py` | 安全网页抓取 |
| `tier_classifier.py` | 来源可信度分级 |
| `citation_verifier.py` | 引用验证 |
| `source_registry.py` | 来源注册管理 |
| `url_utils.py` | URL 工具函数 |
| `blackboard.py` | BlackboardManager |

## 1. Spec Pro (需求规格域)

### 核心职责
将用户的多轮对话转化为结构化的 LivingSpec 需求规格。

### 工作流程

```
Round 1: 用户输入 → Coordinator.init_session()
                     ↓
              ResponseWorker 提取需求
                     ↓
              merge_spec.py → LivingSpec (v1)
                     ↓
              Harness 2.0.0 评估质量

Round 2-6: Coordinator.build_next_round_task()
                    ↓
           ResponseWorker 增量更新
                    ↓
           merge_spec.py → LivingSpec (v2-v6)
                    ↓
           Harness 2.0.0 评估 → 决定是否继续

用户确认: Coordinator.build_confirmation_task()
                    ↓
           LivingSpec 最终版
```

### 关键组件

#### 1.3 Harness 2.0.0 (质量评估)
**文件**: `domains/spec_pro/eval/harness.py`

**两层评估**:
```
Layer 1: S1-S10 (10 项检查)
  S1: 目标清晰度
  S2: 痛点具体度
  S3: 能力完整性
  S4: 约束合理性
  S5: 用户覆盖度
  S6: 质量属性量化
  S7: 集成可行性
  S8: 风险识别度
  S9: 假设合理性
  S10: 需求一致性

Layer 2: SC1-SC2 (语义检查)
  SC1: 推断审计 (InferenceAuditGate)
  SC2: 轨迹审计 (TrajectoryAuditGate)
```

**决策逻辑**:
```python
if all(S1-S10 PASS) and all(SC1-SC2 PASS):
    decision = "PASS"  # 可以进入 Solution Pro
elif any(S1-S10 WARN) or any(SC1-SC2 WARN):
    decision = "WARN"  # 建议继续对话
else:
    decision = "FAIL"  # 必须修复
```

## 2. Solution Pro (解决方案域)

### 核心职责
将 LivingSpec 转化为可执行的技术方案。

### 10 阶段管线

```
Stage 1: Planner
  输入: LivingSpec
  输出: stage_1_planner.json
  职责: 架构设计 + 技术选型

Stage 2: Reviewer (3 位专家)
  输入: Planner 输出
  输出: stage_2_reviewer.json
  职责: 架构/可行性/完整性评审

Stage 3: Fixer
  输入: Reviewer 反馈
  输出: stage_3_fixer.json
  职责: 修复评审问题

Stage 4: Researcher (3 位专家)
  输入: 修复后的方案
  输出: stage_4_researcher.json
  职责: 深度研究 (性能/安全/成本)

Stage 5: Consolidator
  输入: Researcher 输出
  输出: stage_5_consolidator.json
  职责: 合并研究结论

Stage 6: Auditor (3 位专家)
  输入: Consolidator 输出
  输出: stage_6_auditor.json
  职责: 架构/完整性/一致性审计

Stage 7: Fixer
  输入: Auditor 反馈
  输出: stage_7_fixer.json
  职责: 修复审计问题

Stage 8: Harness
  输入: Fixer 输出
  输出: stage_8_harness.json
  职责: 质量评分 (SC1-SC6)

Stage 9: Fixer (条件执行)
  条件: Harness score < 阈值
  输出: stage_9_fixer.json
  职责: 提升质量分数

Stage 10: Summarizer
  输入: 所有阶段输出
  输出: final_result.json
  职责: 生成最终方案
```

## 3. Ship Pro (工程交付域)

### 核心职责
将技术方案转化为可执行的工程包。

### 5 Agent 流水线

```
Stage 1: Architect
  输入: final_result.json
  输出: architect_output.json
  职责: 架构设计 (模块划分、依赖关系)

Stage 2: Specifier
  输入: architect_output.json
  输出: specifier_output.json
  职责: 工作包规格定义 (API/数据模型)

Stage 3: Decomposer
  输入: specifier_output.json
  输出: decomposer_output.json
  职责: 工作包分解 (任务粒度、优先级)

Stage 4: Packager
  输入: decomposer_output.json
  输出: packager_output.json
  职责: 打包 (依赖排序、交付顺序)

Stage 5: Reviewer
  输入: packager_output.json
  输出: ship_package.json
  职责: 最终审核
```

## 4. Research Pro (研究域)

### 核心职责
深度研究特定技术问题。

### 工作流程

```
输入: 研究主题 + 约束条件
       ↓
Orchestrator 编排
       ↓
SearchAgent 搜索 (DuckDuckGo)
       ↓
FetchAgent 抓取 (SafeFetcher)
       ↓
AnalystAgent 分析
       ↓
WriterAgent 撰写报告
       ↓
CitationVerifier 验证引用
       ↓
输出: report/final.md
```

### 关键组件

- `orchestrator.py` - 编排
- `ddgs_client.py` - DuckDuckGo 搜索
- `safe_fetcher.py` - 安全网页抓取
- `citation_verifier.py` - 引用验证
- `source_registry.py` - 来源注册

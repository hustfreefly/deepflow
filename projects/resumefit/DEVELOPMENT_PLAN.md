# ResumeFit 开发计划

> 智能简历生成系统 — 基于 OpenClaw 平台的定制化 PDF 简历引擎
> 版本: v1.0 (MVP)
> 创建时间: 2026-06-01
> 参考: Solution Pro 架构设计、DeepFlow 增量开发方法论

---

## 📋 项目概览

### 核心能力
输入基础简历 + JD（文字/图片）+ 公司信息 → 输出定制化 PDF 简历

### 质量目标
- **保真度**: 90-95%（不造假，仅合理拓展）
- **JD 贴合度**: 高度匹配目标岗位
- **AI 筛选通过率**: 通过主流 ATS/AI 筛选第一关
- **专业度**: 高级呈现，符合行业调性

### 技术约束
- 平台: OpenClaw
- 输出: PDF
- 用户: 个人使用（半导体封装领域）
- 时间: 尽快上线（MVP 10 天）

---

## 🎯 开发原则（参考 DeepFlow）

1. **增量交付**: 每个阶段可独立验证，不依赖后续阶段
2. **声明先行**: 先定义接口契约，再实现内部逻辑
3. **验证驱动**: 每个里程碑有明确的验证标准
4. **最小可行**: MVP 优先，高级功能后置
5. **契约笼子**: 输入输出严格定义，内部实现可灵活调整

## 📦 开发阶段

### Phase 0: 项目基础 (Day 1)

**目标**: 搭建项目骨架，定义核心接口契约

**交付物**:
- 项目目录结构
- 核心接口定义（TypeScript/Python 类型声明）
- 基础配置（OpenClaw skill 注册）
- 开发环境就绪

**接口契约**:
```typescript
// 核心数据结构
interface ResumeFitRequest {
  baseResume: ResumeDocument;      // 基础简历
  jobDescription: JDInput;          // JD（文字或图片）
  companyInfo?: CompanyProfile;     // 公司信息（可选）
  optimizationLevel: 'conservative' | 'standard' | 'aggressive';
}

interface ResumeFitResponse {
  optimizedResume: PDFOutput;       // 生成的 PDF
  qualityReport: QualityMetrics;    // 质量报告
  changesSummary: ChangeLog[];      // 变更日志
}

// 质量指标
interface QualityMetrics {
  fidelityScore: number;            // 保真度 (0-100)
  jdMatchScore: number;             // JD 匹配度 (0-100)
  atsCompatibility: number;         // ATS 兼容性 (0-100)
  aiScreeningScore: number;         // AI 筛选通过率 (0-100)
}
```

**验证标准**:
- [ ] 接口定义文件存在且语法正确
- [ ] 项目可被 OpenClaw 识别为 skill
- [ ] 基础目录结构创建完成

**预估时间**: 0.5 天

### Phase 1: 核心 MVP (Day 2-5)

**目标**: 实现基础流程 — JD 解析 → 内容优化 → PDF 输出

**1.1 JD 解析引擎** (Day 2-3)
- 文本 JD 解析（正则 + LLM 提取）
- 图片 JD OCR（PyMuPDF → PaddleOCR fallback）
- 输出结构化 JD Schema（硬约束 + 软性要求 + 权重矩阵）

**验证标准**:
- [ ] 文本 JD 解析准确率 > 85%
- [ ] 图片 JD OCR 准确率 > 75%（文本型 PDF > 95%）
- [ ] JD Schema 输出格式符合契约

**1.2 内容优化引擎** (Day 3-4)
- 三层次优化：侧重重述 → 关键词注入 → 段落重排序
- 保真度控制（conservative: 95%+, standard: 92%+, aggressive: 90%+）
- 事实锚点保护（公司/职位/时间/学历不可变更）

**验证标准**:
- [ ] 三档优化强度可切换
- [ ] 保真度测试：conservative 模式变更率 < 5%
- [ ] 事实锚点 100% 保留

**1.3 PDF 输出模块** (Day 4-5)
- HTML → PDF 转换（WeasyPrint）
- ATS 兼容格式（单列、标准字体、无页眉关键信息）
- 基础排版（粗体关键词、项目符号、合理间距）

**验证标准**:
- [ ] PDF 生成成功，文件大小 < 2MB
- [ ] 通过 pdfplumber 文本提取验证（非纯图片 PDF）
- [ ] ATS 格式检查通过率 100%

**预估时间**: 4 天

---

### Phase 2: 质量保障 (Day 6-8)

**目标**: 增加校验机制，确保输出质量可控

**2.1 事实校验引擎** (Day 6)
- 生成前：事实锚点锁定（Immutable Anchor Set）
- 生成后：diff + NER 双重校验
- 高风险变更告警（新增公司/项目/技能实体）

**验证标准**:
- [ ] 事实锚点 100% 保留
- [ ] 高风险变更 100% 标记
- [ ] 校验报告输出完整

**2.2 质量报告生成器** (Day 7)
- 6 维自动评分：关键词覆盖率 / 语义相似度 / 内容保真度 / 排版保真度 / ATS 兼容性 / AI 痕迹
- 阈值告警（低于目标自动提醒）
- 变更日志（每个修改项标注来源和风险等级）

**验证标准**:
- [ ] 6 维评分全部可计算
- [ ] 评分与人工评估偏差 < 15%
- [ ] 变更日志可追溯

**2.3 用户交互层** (Day 8)
- JD Schema 确认界面（用户可修正解析错误）
- 拓展强度选择（conservative/standard/aggressive）
- 高风险变更审批（可选）

**验证标准**:
- [ ] 用户可修改 JD Schema
- [ ] 拓展强度切换生效
- [ ] 审批流程可跳过

**预估时间**: 3 天

---

### Phase 3: 智能增强 (Day 9-10)

**目标**: 提升匹配精度和 AI 筛选通过率

**3.1 语义匹配引擎** (Day 9)
- 关键词匹配（ATS 第一道门槛）
- 语义匹配（LLM 内嵌，BGE-M3 可选升级）
- 段落级匹配度热力图

**验证标准**:
- [ ] 关键词匹配准确率 > 90%
- [ ] 语义匹配召回率 > 80%
- [ ] 匹配度热力图可视化

**3.2 AI 痕迹监控** (Day 10)
- 关键词密度上限（单页同一关键词 ≤ 3 次）
- 句式重复率检测
- 自然度评分（0-100，低于 70 告警）

**验证标准**:
- [ ] 关键词密度控制生效
- [ ] 自然度评分可计算
- [ ] 无过度优化告警

**预估时间**: 2 天

## ⚠️ 风险与缓解

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| LLM API 延迟 | 生成时间过长 | 异步队列 + 超时降级（纯模板模式） |
| OCR 精度不足 | 图片 JD 解析失败 | 三级 fallback（PyMuPDF → PaddleOCR → 云端） |
| 保真度失控 | 过度优化导致造假 | 事实锚点 + diff 校验 + 用户确认 |
| ATS 兼容性问题 | PDF 被 ATS 误判 | 单列布局 + 标准字体 + pdfplumber 验证 |

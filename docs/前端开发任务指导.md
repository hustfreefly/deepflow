# DeepFlow 前端开发任务指导

> **创建日期**: 2026-05-16
> **每次操作前必须先读本文档**

---

## 🎯 成功目标

**用前端界面端到端跑通 Solution Pro 任务**：

1. **启动任务** - 前端填写参数 → 提交 → 后端入队 → Cron 自动触发
2. **状态可视化** - ProgressPage 实时显示 9 阶段管线进度（Data → Planning → Reviewers → Researchers → Consolidator → Auditors → Fixer → Harness → Summarizer）
3. **任务完成闭环** - 管线完成 → 前端显示完成 → 可查看报告

**核心**：前端是 DeepFlow 管线的**可视化映射**，不是管线的替代品。

---

## ❌ 禁止项（红线）

| 禁止项 | 原因 |
|:---|:---|
| 修改 Solution Pro 核心代码 | 管线本身是成熟的，不要动 |
| 手动 spawn 任务 | 应该由 Cron/Auto 触发，不是手动跑 |
| 多任务并发 | 不支持 |
| 取消/重试/重新分析 | 不支持 |
| 修改 DeepFlow core 模块 | 契约笼子禁止 |
| 硬编码端口/路径 | 必须从 config.json 读取 |
| `from openclaw import sessions_spawn` 在 exec 环境 | exec 无 openclaw，有 import 就失败 |

---

## ⚠️ 不鼓励

| 不鼓励 | 原因 |
|:---|:---|
| 复杂的通知机制 | 单任务不需要 |
| 批量操作 UI | 不支持多任务 |
| 过度设计状态管理 | 轮询就够了 |
| 改已有的 Orchestrator | 管线是成熟的 |

---

## ✅ 开发原则

| 原则 | 说明 |
|:---|:---|
| **契约笼子优先** | 所有修改必须符合 `frontend_webhook_integration_contract.yaml` |
| **配置驱动** | 端口、路径从 config.json 读取，零硬编码 |
| **前端是映射** | 前端只是管线的可视化映射 |
| **状态流完整** | pending → waiting_agent → running → completed 前端都有对应展示 |
| **离开后可返回** | 首页管线状态卡片是核心修复 |
| **单任务模式** | 一次只跑一个 |

## 📁 当前架构

```
前端 (localhost:17788)
  ├─ App.tsx (首页 + 管线状态卡片)
  ├─ TaskForm.tsx (提交任务)
  ├─ ProgressPage.tsx (管线进度可视化)
  ├─ HistoryPage.tsx (历史记录)
  └─ ReportPage.tsx (查看报告)

后端 (localhost:17789)
  ├─ routers/tasks_v2.py (创建任务 + Webhook)
  ├─ routers/status_v2.py (读取 blackboard/status.json)
  ├─ routers/consumer.py (线程轮询兜底)
  └─ database.py (SQLite 任务队列)

Cron Job (每 2 分钟)
  └─ 检测 pending/waiting_agent → sessions_spawn → Orchestrator

Blackboard (~/.deepflow/blackboard/{session_id}/)
  └─ status.json (管线实时状态)
```

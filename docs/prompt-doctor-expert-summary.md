# Prompt Doctor 专家评审汇总 + AI Native 设计

## 一、三位专家核心观点

### 专家 A（Prompt 工程）

**核心贡献**：补充"上下文契约"作为中间层

| 观点 | 内容 |
|------|------|
| 分层修正 | 两层 → 三层：流程可执行性 → 上下文契约 → 过程质量 |
| 第一层补充 | 重试边界（重试几次？条件如何变化？）+ 中间产物持久化 |
| Agent 理解约束 | 位置即权重（前 500 token）、重复即强调、负面示例 |
| 反模式 | 指令堆砌、隐式状态、无退出兜底、条件模糊、状态靠推理 |

### 专家 B（Agent 架构）

**核心贡献**：明确 Prompt vs Code 归属原则

| 观点 | 内容 |
|------|------|
| 分层本质 | 流程可执行性 = 控制流，过程质量 = 数据流 |
| 完成条件 | 必须双层：Prompt 声明语义完成 + 代码强制系统完成 |
| 归属原则 | 控制流归代码（确定性），语义判断归 Prompt（灵活性）|
| Skill 定位 | Prompt Doctor = IDE lint（写 Prompt 时的语法检查器）|

### 专家 C（质量工程）

**核心贡献**：验证分层 + 可观测性

| 观点 | 内容 |
|------|------|
| 补充第三层 | 可观测性（执行耗时、重试次数、token 消耗）|
| 验证分层 | 代码验证格式、LLM 验证语义、Prompt 约束流程 |
| 质量定义 | 人定义 golden example，LLM-as-Judge 自动验证 |
| Skill 边界 | AgentDryRun=体检，Doctor=监护，Prompt Doctor=诊断+开方 |

## 二、共识与分歧

### 共识（3/3 一致）

1. ✅ 两层分层基本正确，优先级：流程可执行性 > 过程质量
2. ✅ 需要补充"上下文契约"维度
3. ✅ 验证应该分层：代码 + Prompt + LLM
4. ✅ Prompt Doctor 定位：轻量级 Prompt 结构检查

### 分歧

| 议题 | 专家 A | 专家 B | 专家 C |
|------|--------|--------|--------|
| 第三层 | 上下文契约 | （无独立第三层）| 可观测性 |
| 完成条件归属 | Prompt 层 | 代码层强制 | 混合 |

**我的裁决**：
- 第三层 = 上下文契约（专家 A），因为可观测性更偏代码层，不是 Prompt 设计维度
- 完成条件 = 双层（专家 B），Prompt 声明语义 + 代码强制验证

## 三、结合 AI Native 导向的设计

### 3.1 能力正交（三公理之一）

| 层 | 职责 | 工具 |
|----|------|------|
| **代码层** | 格式验证、状态机控制、重试计数、超时检测 | Pydantic、状态机、计数器 |
| **LLM 层** | 语义理解、质量判断、失败原因分析 | LLM-as-Judge |
| **Prompt 层** | 任务边界、完成语义、质量预期、退出策略 | Prompt 指令 |

**核心原则**：控制流归代码，语义判断归 Prompt，两者通过 blackboard 文件交互。

### 3.2 契约铁律（三公理之二）

Prompt 不是"指令列表"，是"协作契约"：

```
❌ 传统思维：你是 XXX Agent。你必须做 A、B、C。如果失败，重试。
✅ 契约思维：角色与边界 + 状态流转表 + 完成条件 + 数据流契约
```

### 3.3 信息守恒（三公理之三）

每步的输入源、输出目标、中间产物位置必须显式声明，确保信息无损流转。

## 四、最终 Skill 设计

### 4.1 三层架构

```
┌─────────────────────────────────────────┐
│  Layer 3: 上下文契约（Context Contract）  │
│  - 每步的输入源、输出目标、中间产物位置    │
├─────────────────────────────────────────┤
│  Layer 2: 过程质量（Process Quality）     │
│  - 质量预期、验证标准、示例                │
├─────────────────────────────────────────┤
│  Layer 1: 流程可执行性（Flow Executability）│
│  - 任务边界、状态流转、完成条件、退出机制  │
│  - 前置条件，不通则后续为零               │
└─────────────────────────────────────────┘
```

优先级：Layer 1 > Layer 3 > Layer 2

### 4.2 Skill 定位

| Skill | 类比 | 时机 | 方法 |
|-------|------|------|------|
| **Prompt Doctor** | IDE lint | 写 Prompt 时 | 结构检查 + 语义分析 |
| **AgentDryRun** | 集成测试 | 改完后 | 六维体检（静态，全面） |
| **Doctor** | 急诊室 | 跑挂了 | 动态诊断（运行时） |

### 4.3 检查清单（摘要）

**Layer 1（必须）**：
- [ ] 任务边界声明
- [ ] 状态转移表
- [ ] 完成条件（成功 + 失败）
- [ ] 退出机制（重试上限 + 失败输出）

**Layer 3（必须）**：
- [ ] 输入源定义
- [ ] 输出目标定义
- [ ] 中间产物清单

**Layer 2（推荐）**：
- [ ] 质量预期（golden example）
- [ ] 验证标准
- [ ] 正面 + 负面示例

# 专家 #2 评审 — 视觉设计师

## 评分（1-10）

| 维度 | 评分 | 简评 |
|------|------|------|
| 视觉层次 | **6/10** | 层级存在但被信息密度稀释，卡片缺乏视觉权重差异 |
| 配色方案 | **7/10** | Tailwind 调色板一致且和谐，但颜色种类偏多造成视觉噪音 |
| 空间布局 | **7.5/10** | Grid 对齐工整，留白克制但专业，响应式设计完整 |
| 字体排版 | **5.5/10** | 字号跨度大（11px→36px）但缺乏系统型阶，部分文本可读性不足 |
| 整体美学 | **7/10** | 像"2024 SaaS Dashboard"多过"系统架构图"，好看但方向偏移 |
| **总评** | **6.6/10** | 视觉功底扎实，但需要回归架构图的本质——清晰传递系统结构 |

## 关键发现

### 1. 统计卡片抢戏 —— 这是架构图，不是仪表盘

顶部 Header 的 `.stats` 区域（188K 行、1,481 文件、4 模块…）以 `28px` 加粗数字 + 蓝色高亮呈现，视觉权重等同于甚至超过层级标题。用户第一眼看到的是项目统计数据，而非系统结构。

**问题**：架构图的核心目的是展示组件关系和数据流向，不是项目概览仪表板。这些统计信息更适合放在页脚或侧边栏作为辅助信息。

### 2. 颜色系统过度膨胀 —— 5 层色 + 4 域色 + 4 文件色 = 13 种语义色

整个页面使用了：
- 5 种层级边框色（蓝/紫/粉/绿/黄）
- 4 种 Domain 顶条渐变色（蓝/紫/粉/绿）
- 4 种文件类型标签色（蓝/紫/绿/黄）
- Legend 又是 5 种颜色圆点

**结果**：用户需要反复对照 Legend 才能理解颜色含义。好的架构图应该在 3 秒内让读者理解颜色编码，这里需要 10 秒以上。

### 3. 连接器设计过于简陋

层间连接器仅用 `▼ text ▼` 形式，配色单薄（`#444`），与周围精致的卡片/圆角/渐变形成强烈反差。连接器是架构图的"动脉"——数据流的方向和方式比静态层级更重要，但这里的连接器看起来像占位符。

### 4. 卡片视觉权重扁平化

所有 `.card` 使用相同的 `background: rgba(255,255,255,0.03)` + `border: rgba(255,255,255,0.08)`，无论内容重要性。L0 OpenClaw 宿主层（最顶层抽象）和 L1 里的"脚本 & 工具"卡片在视觉上完全平等。

**架构图需要视觉权重**：核心组件应更突出，辅助组件应退后。

### 5. Domain 卡片内容过载

每个 Domain 卡片塞入了：标题 + 描述 + 3 个统计 + 文件列表（核心逻辑/Prompts/契约分三组）+ 执行管线。以 Spec Pro 为例，文件标签就有 17 个之多。

**问题**：这不是文件目录浏览器，这是架构图。文件级别细节应该折叠或摘要化。

### 6. 缺少数据流可视化

图中有 "sessions_spawn + exec"、"domain dispatch + spawn Workers"、"Blackboard 文件读写" 等文字标注在连接器上，但没有任何视觉化的数据流——没有箭头宽度变化、没有流向动画暗示、没有协议类型图标。读者需要靠文字理解组件间如何通信。

### 7. 字体排版缺乏系统型阶

| 用途 | 字号 | 问题 |
|------|------|------|
| 主标题 | 36px | ✅ 清晰 |
| 副标题 | 15px | ✅ 可接受 |
| 统计数字 | 28px | ⚠️ 过大，抢戏 |
| 统计标签 | 12px | ✅ |
| 层级标签 | 11px | ⚠️ 偏小，且 uppercase + letter-spacing 进一步降低可读性 |
| 卡片标题 | 16px | ✅ |
| 卡片项 | 12px | ✅ |
| 行号信息 | 11px + `#666` | ❌ 对比度太低，几乎不可读 |
| 连接器标签 | 11px + `#666` | ❌ 同上 |
| Domain 标题 | 18px | ✅ |
| Domain 描述 | 13px + `#888` | ⚠️ 对比度偏弱 |
| 管线步骤 | 12px | ✅ |

字号种类超过 10 种（11/12/13/15/16/18/28/36），缺乏明确的 3-4 阶系统。

## 具体改进建议（按优先级排序）

### 🔴 必须改

1. **移除或降级顶部统计卡片**
   将 188K/1,481/4/6 等统计数据移到页脚或缩小为 Header 副标题下方的单行小字。架构图的第一视觉焦点应该是层级结构，不是项目规模。

2. **减少颜色语义种类到 5-7 种**
   建议方案：
   - 层级边框色统一为 **2 种**（核心层蓝色 + 支撑层灰色），仅用标签文字区分层名
   - Domain 卡片顶条色统一为 **1 种**（紫色系渐变），靠标题图标和文字区分模块
   - 文件类型色保留 **3 种**（.py 蓝 / .md 紫 / .yaml 绿），去掉 .json 黄色（可归入 .py 或灰色）
   - 总颜色语义从 13 种降到 6 种

3. **重绘连接器为视觉化数据流**
   用 SVG 箭头替代 `▼ text ▼`：
   - 箭头宽度可暗示数据量/重要性
   - 箭头旁用图标标注通信协议（📡 = API, 📄 = 文件, 🔌 = 事件）
   - 至少使用 `stroke-width: 2px` + `#4a90d9` 替代当前 `#444`

### 🟡 建议改

4. **建立卡片视觉权重层级**
   - 核心组件（如 Blackboard、Unified Entry）：增加内边距（24px→28px）+ 稍亮背景（0.03→0.05）+ 微妙的左侧色条（3px accent border）
   - 辅助组件（如 scripts/、maintenance/）：缩小内边距 + 降低背景透明度（0.03→0.015）+ 灰色边框

5. **Domain 卡片信息折叠**
   将文件列表从完整罗列改为摘要格式，例如：
   ```
   📁 核心逻辑 · 7 个文件
   📁 Prompts · 8 个文件  
   📁 契约 · 1 个 active cage
   ```
   保留执行管线（这是架构图需要的），但文件列表可以折叠或改为 hover 展开。

6. **字体排版简化为 4 阶系统**

   | 阶 | 字号 | 用途 |
   |----|------|------|
   | H1 | 32px | 主标题 |
   | H2 | 18px | 层级标签 / Domain 标题 |
   | Body | 14px | 卡片内容 / 描述 |
   | Caption | 12px | 行号 / 辅助信息 |

   去掉 11px、13px、15px、16px、28px、36px 等中间值。

7. **提高低对比度文本的可读性**
   `#666` 在 `#0a0a0f` 背景上的对比度约为 3.7:1，低于 WCAG AA 标准（4.5:1）。建议提升至 `#999` 或更浅。

### 🟢 可选改

8. **添加微妙网格背景**
   在 `body` 背景上添加极淡的网格线或点阵（`rgba(255,255,255,0.02)`），增强"技术架构图"的质感，区别于通用 Dashboard。

9. **Layer 标签增加图标**
   当前 layer-label 只有文字（"L0 · OpenClaw 宿主层"），可在标签前加小图标增强识别：
   - L0: `🦞` 或 `⚡`
   - L1: `⚙️`
   - L2: `🧩`
   - L3: `💾`
   - L4: `🌐`

10. **增加打印/导出优化**
    添加 `@media print` 样式，确保导出 PDF 时深色背景转为浅色背景（或保持深色但优化墨水使用）。

## 视觉设计方向推荐

### 方向 A：技术蓝图风格（Technical Blueprint）⭐ 推荐

**参考**：AWS Architecture Diagrams、Kubernetes 架构图、Mermaid 默认风格

- **浅色背景**（`#f8f9fa`）+ 深色文字
- **正交连线**（直角折线而非曲线）
- **组件用矩形**，少用圆角（`border-radius: 4px` 或 `8px`）
- **颜色克制**：最多 4 种语义色，其余用灰阶区分层级
- **网格点阵背景** 增强技术感

**理由**：这是系统架构图，不是营销落地页。技术团队需要的是快速理解系统结构，而不是视觉惊艳。蓝图风格在工程团队中认知度最高，打印友好，且避免了"AI 生成的 SaaS 风"。

### 方向 B：暗色终端风格（Dark Terminal）

**参考**：GitHub Dark、VS Code 主题、Terminal UI

- 保持当前深色背景
- 引入 **monospace 字体** 用于文件路径和代码引用
- 连接线使用 **虚线/点线** 暗示数据流
- 颜色减少为 **终端色**（绿 `#22c55e`、黄 `#eab308`、红 `#ef4444`、蓝 `#3b82f6`）
- 去除所有渐变，改用纯色 + 透明度

**理由**：DeepFlow 是开发者工具，暗色终端风格与目标用户的技术审美高度一致。monospace 字体用于文件路径是自然的隐喻。但需要避免变成"看起来像终端截图"。

### 方向 C：信息图风格（Infographic）

**参考**：Stripe 技术博客插图、Vercel 架构图

- 保持深色主题但增加 **插画元素**（简化的服务器/数据库图标）
- 使用 **柔和渐变** 但限制在 2-3 个主色调
- 组件间用 **曲线连接** 增加流动感
- 增加 **编号标注**（① ② ③）暗示执行顺序
- 统计信息以 **小型信息图元素** 融入层级卡片内

**理由**：如果架构图需要对外展示（技术分享、招聘、文档首页），信息图风格最具视觉吸引力。但需要克制——过度装饰会让架构图变成海报。

---

> **一句话总结**：当前版本视觉功底扎实，但"Dashboard 感"太强。架构图的第一目标是**让读者在 10 秒内理解系统结构**，而不是让读者说"这个页面很好看"。建议在方向 A（技术蓝图）的基础上保留当前设计的精致度。

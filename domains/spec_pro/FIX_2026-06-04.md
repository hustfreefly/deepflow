# Spec Pro 契约笼子修复 — 2026-06-04

## 修复清单

### P1: is_done() 不识别 proposal/summary action
- **文件**: `coordinator.py`
- **修复**: `is_done()` return 表达式从 `("done", "error", "safety_stop")` 扩展为 `("done", "error", "safety_stop", "proposal", "summary")`
- **根因**: `_collecting_phase_instructions()` 的停滞检测分支会输出 `action: "proposal"`，质量达标分支输出 `action: "summary"`，但 `is_done()` 不识别这两个 action，导致可能继续追问
- **影响**: 停滞检测和达标检测可能不触发结束，用户会被多问一轮
- **验证**: AST 检查 + 语法检查 ✅

### P2: build_confirmation_task() 缺少 v3_flat 分支
- **文件**: `coordinator.py`
- **修复**: 
  - `build_confirmation_task()` 增加 `if self.architecture_version == "v3_flat"` 分支
  - 新增 `_build_v3_confirmation_task(round_num)` 方法，生成主 Agent 直接执行的确认指令
- **根因**: 该方法总是调用 `_build_orchestrator_task()`（v2 风格），包含 "spawn StructureWorker" 指令，但 v3 架构下主 Agent 不 spawn Worker
- **影响**: 确认阶段主 Agent 可能收到不一致的指令
- **验证**: 方法存在 + 包含 confirm/revise/round_result/done 要素 ✅

### P3: 死代码标注 + 文档补强
